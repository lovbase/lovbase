# 任务实时状态与完成通知技术方案

更新日期：2026-10-27。本文功能已经上线。

## 修改范围

仅将下列三处前端轮询改为 SSE：

| 功能 | 当前方式 | 修改后 |
| --- | --- | --- |
| 任务状态 | 运行期间每 1.5 秒查询 | 创建、排队、运行、进度、结束等状态变化后推送，并同步持久化的当前状态 |
| 构建活动 | 每 1.8 秒查询 | 沙箱进程输出、活动文件追加和进程退出时推送，保持现有步骤、文字和代码展示语义 |
| 站内通知 | 每 5 秒查询 | 通知产生、标为已读时推送，同步未读列表和数量 |

支付确认、表格导入、工作区运行状态、分析页面、PWA 更新检查等其他轮询保持现状。现有聊天内容流保持现状。本方案不修改订阅套餐。

## SSE 传输与恢复

- 页面复用经过身份认证的 SSE 连接；用户、项目和应用范围均在服务端校验，禁止跨用户订阅。
- Web 与 Worker 跨进程事件由持久化状态的提交事件驱动，计划使用 PostgreSQL LISTEN/NOTIFY。事件用于通知状态变化，数据库仍是最终状态来源，不将原有定时查询转移到 SSE 服务端。
- 先建立事件订阅，再读取初始快照；按作用域合并高频变化，避免初始化丢事件和并发快照倒序覆盖。SSE 心跳只维持连接，不查询业务状态。
- SSE 断线后保留自动重连，并在重连后重新读取当前任务状态、最新构建活动和站内通知。允许用最新持久化状态补齐断线期间的变化。
- 沙箱活动通过 Docker / Cloudflare 的流式执行与文件监听能力提供真实增量流。每次生成复用一个上游活动流，通过 Redis 分发给页面；以运行 ID、文件字节游标和租约代次隔离，处理文件重置、重连和旧运行事件。
- 保留现有聊天流与恢复机制，避免较旧的保存消息覆盖正在流式展示的内容。页面断开 SSE 不取消或重新执行任务。

## Web Push 完成通知

- 使用真正的 Push API、Service Worker 和 VAPID；关闭页面后，在浏览器和系统支持且已授权的条件下仍可接收。
- 用户主动开启后保存设备订阅；同一账号所有有效且已启用的设备都接收完成通知。旧的本地通知偏好不自动视为 Push 授权。
- 仅在任务首次进入符合条件的成功终态后发送：成功生成应用，或成功完成 build / publish。普通对话、取消和失败任务不发送 Web Push；现有站内失败通知保持。
- 任务结果先持久化，再按设备订阅各尝试发送一次，设置单次请求超时。**只有 Web Push 消息发送失败不重试，允许静默丢失**；不使用重试队列、补发或历史回填，进程中断造成漏发也可接受。
- Web Push 失败不改变任务状态、计费或站内通知，不向客户弹出发送失败错误。404 / 410 清理失效订阅；其他失败只记录必要诊断信息，不记录完整 endpoint、密钥或敏感载荷。
- 订阅的注册、续订、取消及账号/会话失效清理与消息投递分开处理；发送失败不重试的规则不扩展到这些操作。订阅设置失败允许用户手动重试。
- Service Worker 接收 push 并展示通知，复用现有通知点击跳转与同源校验。移除原先依赖页面轮询触发的系统通知，避免与 Web Push 重复展示系统通知。
- 未授权、不支持 Push 或未配置 VAPID 时，继续提供站内通知；不要求客户保持页面打开以接收 Web Push。

## 保持的业务逻辑与重试

任务执行、排队、取消、超时、计费、成功/失败判定和站内通知规则保持原样。本次改变状态的传递方式，并增加独立的成功通知投递。

**除 Web Push 消息发送外，原来有重试的地方继续保留重试。** 包括沙箱/API 请求重试、队列重投与恢复、任务恢复、聊天流恢复、SSE 自动重连及状态重同步。沙箱执行完成协议（包括现有 `/run/poll`）、心跳和租约机制不在这三处前端轮询的替换范围内。

SSE 不是任务成功的前提；Web Push 也不是任务成功的前提。不得因为通知发送失败中断正常恢复机制。

## 验收

1. 三处原有 1.5 秒、1.8 秒、5 秒定时请求消失，状态和活动由事件触发；其他轮询按原样运行。
2. 验证任务排队、执行、成功、失败、取消，以及构建活动展示和通知已读同步，业务结果与改造前一致。
3. 验证断网重连、刷新、跨 Web/Worker 进程与多设备场景；恢复后展示最新状态，隔离不同用户与运行。
4. 开启 Push 后，符合条件的任务成功时每个有效订阅最多尝试一次；失败、超时、进程中断均不触发自动补发，也不影响任务结果和站内通知。
5. 对比改动前后非 Push 重试、任务恢复和聊天流恢复路径，确认未因静默投递策略被移除或禁用。
